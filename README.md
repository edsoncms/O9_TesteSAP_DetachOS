## 📖 About This Project

**O9_TesteSAP_DetachOS** is a **Traditional Web** application originally built on **OutSystems 9 (O9)** with a **SAP system integration**, exported via the platform's **Detach** process. This repository showcases the source code as generated by OutSystems at the time of contract closure, serving as a technical reference for teams analyzing code quality and portability from the OutSystems platform.

This is a **companion repository** to [ContactManager (O11)](https://github.com/ms3ti/ContactManager), which demonstrates the same Detach process but from **OutSystems 11**. Together, they illustrate how the platform evolved its code generation across major versions.

---

## 🎯 Goals of This DEMO

- ✅ Illustrate the **source code quality** exported by OutSystems 9 during Detach
- ✅ Demonstrate a **SAP-integrated Traditional Web** application after Detach
- ✅ Include **SQL scripts** used to support the application's data layer
- ✅ Serve as a **historical reference** comparing O9 vs O11 generated code structure
- ✅ Support analysis for teams evaluating **OutSystems contract exit strategies**

## 🔄 What is the OutSystems Detach Process?

The **Detach** (also known as *Take Ownership*) is a formal process offered by OutSystems that allows customers to extract the full generated source code of their applications — typically performed at **contract termination**. Once detached:

- The application runs as a **pure ASP.NET application**, independent of the OutSystems platform
- The source code is fully readable, compilable, and maintainable by any .NET developer
- All **SAP integration logic** defined in Service Studio is exported as plain C# code
- **SQL scripts** are included to recreate the database schema independently

This is particularly relevant for companies going through **OutSystems offboarding**, ensuring business continuity and code ownership after the platform license ends.

---

## 🔌 SAP Integration Highlight

One of the key aspects of this demo is the **SAP integration layer** exported by OutSystems. The generated code demonstrates:

- RFC/BAPI calls to SAP systems implemented as standard C# classes
- Integration logic that was originally built using OutSystems' visual IDE (Service Studio), now fully visible as readable source code
- Clear separation between the web layer (ASP.NET) and the SAP connectivity layer

This is strong evidence that OutSystems does **not lock in** integration logic — it generates transparent, auditable code.

### Sobre este Repositório

O **O9_TesteSAP_DetachOS** é uma aplicação **Traditional Web** desenvolvida no **OutSystems 9 (O9)**, com **integração ao SAP**, exportada através do processo de **Detach da plataforma** no encerramento de contrato com a OutSystems. Este repositório tem como objetivo demonstrar a qualidade e estrutura do código gerado pela plataforma na versão 9.

> ⚠️ **Este projeto é apenas para fins de estudo e análise de qualidade de código. Não é uma aplicação pronta para produção.**

### Contexto

Este código foi extraído durante o **encerramento de contrato com a OutSystems**, demonstrando que todo o código-fonte da aplicação — incluindo a lógica de integração com o SAP — é exportado de forma legível e reutilizável, sem dependência da plataforma para execução futura.

### Estrutura

- **`Teste_SAP_v4_Source/`** — Código-fonte principal da aplicação Traditional Web em ASP.NET, gerado pelo OutSystems 9
- **`Scripts SQL/`** — Scripts T-SQL para SQL Server para criação do schema do banco de dados

### Tecnologias

- **C#** — 91,8% do código (lógica de negócio, telas, integração SAP)
- **JavaScript** — 5,1% (widgets e interações de UI)
- **ASP.NET** — 2,6% (handlers e configurações web)
- **CSS** — 0,4% (estilos customizados)
- **T-SQL** — Scripts para SQL Server (pasta `Scripts SQL/`)
- Plataforma de origem: **OutSystems 9 Traditional Web**
- Integração: **SAP via RFC/BAPI**

### Destaque: Integração com SAP

Um dos pontos mais relevantes desta DEMO é a **camada de integração com o SAP** exportada pelo OutSystems. O código gerado mostra chamadas RFC/BAPI ao SAP implementadas como classes C# padrão — demonstrando que a lógica de integração construída visualmente no Service Studio é convertida em código transparente e auditável.

### Comparativo com a versão O11

Este repositório pode ser comparado ao [ContactManager (O11)](https://github.com/ms3ti/ContactManager) para observar a evolução da plataforma OutSystems na geração de código entre as versões 9 e 11: maior modularização, suporte a múltiplos bancos de dados, plugins de mensageria e uma estrutura de runtime muito mais robusta na versão 11.

### Objetivo

Demonstrar que o OutSystems **não é uma caixa-preta** — mesmo na versão 9, a plataforma gera código .NET legível, compilável e totalmente portável, incluindo integrações com sistemas externos como o SAP.
